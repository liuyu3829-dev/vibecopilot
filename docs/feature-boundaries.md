# Thought Space 功能边界与回归契约

> 状态：2026-08-06。本文是后续所有功能迭代的保护边界；新增功能必须扩展，不得改写或破坏已验收能力。

## 1. 已验收的核心能力（冻结）

### 桌面悬浮球

- Windows 悬浮球透明、无可见方形底图、始终置顶，并可在桌面任意拖动。
- 点击球体展开紧凑的玻璃录音卡；关闭/收起后回到球体。
- 网页的“显示 / 隐藏桌面悬浮球”只改变已运行球体的可见性，必须即时完成，不能新建第二个进程或终端窗口。
- 球体和网页使用同一套思想保存接口；桌面保存后，网页时间线可读取同一条记录。
- 视觉细节包括：中央发光球、无左上角标题、可编辑且可滚动的文字区、真实麦克风采样驱动的声波线，以及紧凑的开始录音和保存操作。

### 实时捕捉与保存

- 仅在用户明确开始录音后请求麦克风；停止后必须关闭音轨、音频图和 WebSocket，且不再继续采集音频。
- 浏览器和桌面端均使用 AssemblyAI 实时转写。音频只在内存和实时连接中流转，不保存音频文件。
- 原始转写是用户内容：不可被 AI 覆盖、翻译、重复拼接或无故改写；应保持去重和自动断句/标点行为。
- 手动输入始终可用。空文本不能创建思想。
- 每次确认保存只创建一条思想；保存失败必须明确提示，不能静默丢失文本。

### 思想、分析与日报数据

- `GET/POST /api/thoughts`、`PATCH/DELETE /api/thoughts/:id` 和 `/api/speech/session` 是现有兼容接口；后续功能不得随意改名、改变请求/响应形状或将密钥暴露给客户端。
- 思想包含原始转写、来源、时间、语言、摘要、标签、分析状态和软删除时间。删除采用软删除。
- DeepSeek 分析在服务端执行；分析失败不阻断思想保存，允许重试。
- 日报只读取当天未删除思想；报告生成与保存不能修改原始思想文本。
- 当前开发模式可使用本地 SQLite；未来云端模式可使用 Supabase。两者都必须通过 `ThoughtStore` / `ReportStore` 边界，不把数据库细节带进 UI 或录音模块。

## 2. 当前明确不在本轮范围内

- 邮箱验证码登录、正式 Supabase 云端迁移、邮件服务、域名、公开部署和安装包分发。
- 多用户权限、RLS 策略、账户同步、数据迁移、支付或开机自启。
- Mac 版本、移动端原生应用、全局快捷键、后台持续监听。
- 搜索、周报、设置页及未明确确认的导航项。

这些项目可以作为独立任务推进，但任何一个都不能以“重构”为名改坏第 1 节的能力。

## 3. 下一轮：日历 / 日记功能的安全边界

下一轮允许新增日历和日记展示，但它必须是思想数据的**消费方**，不是录音、保存或桌面球的替代实现。

允许：

- 新增独立路由或组件，例如日历视图、按日期聚合、单日阅读页和美观的日记排版。
- 读取既有思想记录，以 `capturedAt` 归档；读取摘要、标签和日报作为辅助信息。
- 新增只读的日期筛选/聚合查询，或在既有列表接口上增加向后兼容的可选日期参数。

禁止：

- 修改 AssemblyAI 录音流程、音频编码、转写去重、停止清理和桌面球拖动/显示逻辑。
- 为了日记排版而写回、翻译、覆盖或拆分原始 `transcript`。
- 改变桌面端保存来源 `desktop_orb`、现有思想 API 的默认行为或已验收的网页时间线。
- 在日历页面中引入登录拦截、数据库迁移或 Supabase 强依赖；这些属于单独的登录/云端任务。

## 4. 后续登录与部署的边界

- 登录完成后只负责提供用户身份；它不拥有录音、声波、悬浮球窗口或思想编辑 UI。
- 数据库切换只能替换 `ThoughtStore` / `ReportStore` 的实现，不能改变捕捉、保存和日历的业务调用方式。
- 本地开发的认证旁路只能作为开发配置存在。恢复登录时必须保留本地模式可测试的路径，不能让没有邮箱会话的开发环境变成 404 或白屏。
- 正式安装包应连接部署后的 HTTPS API；最终用户不安装 Node、Rust、Visual Studio 或在终端运行服务。

## 5. 改动规则与验收

1. 每次任务开始前，先指出会触及的边界和不会触及的冻结模块。
2. 改录音、桌面球、保存或协议唤起前，必须先写失败测试，再实现。
3. 修改桌面球相关代码后，至少运行 `npm test`、`npm run typecheck`、`npm run build`；并保留桌面壳编译检查。
4. 修改日历/日记时，必须验证：原有录音、保存、编辑、删除、桌面球显示/隐藏仍可用，且日记视图不会改写原始转写。
5. 如果新需求与本文冲突，先向产品负责人说明冲突并获得明确批准；不得自行牺牲已验收能力。

## 6. 责任划分速查

| 模块 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 桌面悬浮球 | 原生窗口、拖动、显示/隐藏、录音卡和桌面捕捉 | 日历排版、登录邮件、数据库迁移 |
| 捕捉模块 | 麦克风、AssemblyAI 实时转写、停止清理、去重与标点 | 日记展示、用户账户 UI |
| 思想 API / Store | 保存、读取、编辑、软删除、AI 分析状态 | 原生窗口与日历视觉 |
| 日历 / 日记（下一轮） | 按日期阅读和美观呈现既有思想 | 改写原文、改录音链路、控制桌面球 |
| 登录 / 云端（后续） | 身份、会话、云端数据隔离和部署 | 改变既有捕捉和桌面交互体验 |
